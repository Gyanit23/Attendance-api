# REVIEW.md

Review of the starter `app/main.py`. Line numbers refer to the original starter file.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` (l.22) | Client is not `tz_aware`, so PyMongo returns **naive** datetimes. | `compute_overtime` builds an IST-aware `end` and subtracts a naive `punch_out` -> `TypeError: can't subtract offset-naive and offset-aware datetimes` -> 500 on any punch-out/regularize. | `MongoClient(..., tz_aware=True, tzinfo=UTC)`; every datetime is also passed through `as_utc()`. |
| 2 | `compute_late_minutes` (l.33-37) | (a) `minutes > 10` is wrong: 09:40:01 is 10 min 1 s, `int()` gives 10, so it returns 0 (R2 says 10). (b) Shift start is built on the punch-in's *own* date and in the server's local zone, not IST, and not on the attendance date, so overnight shifts are wrong. (c) Seconds are not truncated first. | Shift 09:30, punch 09:40:01 -> expected 10, got 0. Overnight 22:00 shift, punch-in 01:00 next day -> negative/0 instead of 180. | Rewritten: anchor `shift_start` on the attendance date in IST; `late = delta//60 if delta_seconds > 600 else 0`. Instants truncated to whole seconds at the API boundary. |
| 3 | `compute_work_hours` (l.40-41) | Python `round()` is banker's rounding on a binary float, not half-up. | punch-in to punch-out of 3618 s = 1.005 h: expected 1.01 (half-up), starter returns 1.0 because the float is 1.00499999... | `Decimal(seconds)/Decimal(3600)` quantized with `ROUND_HALF_UP`. |
| 4 | `compute_overtime` (l.44-47) | (a) No 30-minute minimum (R3): 1 min after shift end counts. (b) End is always on the attendance date, so an overnight shift (end 06:00 next day) gives a hugely wrong value. (c) `fromisoformat(date).replace(...)` on a date string. | Shift 09:30-18:30, punch-out 18:35 -> returns 5, expected 0. Sample #7 (22:00-06:00, in 21:55, out 06:40 next day) -> returns 1480 instead of 40. | New `compute_overtime(punch_out, day, start, end)`: shift end is `day + shift_end` (+1 day if overnight), floor minutes, `>= 30` else 0. |
| 5 | `EmployeeIn` (l.53-60) | No validation at all: any `emp_code`, bad email, `shift_start == shift_end`, `joined_on` like `"2026-02-30"` or `"hello"`, blank name, unlimited lengths. Client could also send `created_at`. | `POST /employees` with `{"emp_code":"x","joined_on":"abc",...}` -> 201. | Pydantic constraints from the contract (regexes, lengths), blank check, real-date check, `shift_start != shift_end` model validator -> 422. |
| 6 | `create_employee` (l.77-85) | Check-then-insert race and no unique index: two concurrent creates both pass `find_one` and both insert (duplicate emp_code). `created_at = datetime.now()` is naive *local* time and is returned as a datetime, not epoch ms. | 20 parallel POSTs with the same emp_code -> several 201 and duplicate documents. | Unique index on `emp_code`; `insert_one` and catch `DuplicateKeyError` -> 409. `created_at` is UTC, returned as epoch ms. |
| 7 | `list_employees` (l.88-96) | (a) `skip = page * page_size` is off by one: page 1 skips the first page. (b) `total` is `count_documents({})`, ignoring the department filter. (c) No sort, so order is not `emp_code`. (d) No bounds on `page`/`page_size`: `page=0` gives a negative skip (500), `page_size=10**9` is unbounded. (e) `created_at` leaks as a datetime. | `?page=1&page_size=2` returns employees 3-4; `?department=Sales` returns `total` of all employees. | `skip=(page-1)*page_size`, `count_documents(q)`, `.sort("emp_code")`, `Query(ge=1)` / `le=100` -> 422, serialiser converts dates. |
| 8 | `punch_in` (l.101-102) | Unknown employee: `emp` is `None`, then `emp["shift_start"]` raises `TypeError` -> **500** instead of 404. | `POST /attendance/punch-in {"emp_code":"EMP9999"}`. | Explicit 404 before anything else. |
| 9 | `punch_in` (l.102-103) | `datetime.fromtimestamp(ms/1000)` is naive server-local time; `ts.date()` is therefore not the IST date (R1). `if body.punched_at` treats `0` as "missing". Microseconds are not truncated. | Server in UTC, punch at 00:10 IST -> record dated the previous day. | `ms_to_dt` (UTC, truncated to the second) + `attendance_date()` converts to IST. `is not None` check. |
| 10 | `punch_in` (l.103) | Overnight rule of R1 is missing: a punch-in before `shift_end` of an overnight shift must belong to the previous day. | Meera (22:00-06:00) punches in at 05:30 IST -> record gets today's date instead of yesterday's. | `attendance_date()` implements R1 incl. overnight; late is anchored on that date. |
| 11 | `punch_in` (l.104-118) | Check-then-insert race again: two simultaneous requests both see "no record" and both insert -> two 201 / duplicate day. | Fire 10 identical punch-ins in parallel -> more than one 201. | Unique compound index `(emp_code, date)` and `DuplicateKeyError` -> 409 (the database is the arbiter). |
| 12 | `PunchInIn` (l.63-66) | `status: str` accepts `ABSENT`, `LEAVE` or any garbage; `punched_at: int` (lax mode) accepts `"123"`, `1.0`, seconds-sized values, negative numbers. | `{"status":"ABSENT"}` creates an ABSENT record with a punch-in; `{"punched_at": 1783312500}` (seconds) is accepted and lands in 1970. | `Literal["PRESENT","WFH","ON_DUTY"]` and a strict `EpochMs` type (`strict=True`, `100000000000 <= v <= 4102444800000`). |
| 13 | `punch_in` response (l.119-121) | Returns `"id": str(ObjectId)` (internal `_id` must never leave the API) and returns `punch_in` as a datetime object instead of epoch ms. | Response contains `id`; `punch_in` is an ISO string. | `record_out()` serialiser: no ids, ms for every instant, defaults for legacy fields. |
| 14 | `list_attendance` (l.144-150) | Loads the **whole collection** into memory, sorts and slices in Python: ~100k docs per request, memory spike, slow. Sort is by `date` only (no `emp_code` tie-break; contract wants date desc, emp_code asc). | `GET /attendance` on 100k docs takes seconds; `explain` shows COLLSCAN. | `find().sort().skip().limit()` in the database, `count_documents(q)` for `total`, compound indexes that match the sort. |
| 15 | `list_attendance` (l.125-150) | No validation: `date_from > date_to`, malformed dates, unknown `status`, `page=0` (slice `docs[-20:0]` silently returns `[]`), unlimited `page_size`. Legacy records (no `half_day`/`history`) are returned without those fields, and history dates are not converted. Also leaks `id`. | `?page=0` returns 200 with empty items; `?date_from=2026-07-10&date_to=2026-07-01` returns 200. | `build_attendance_filter` validates and returns 422; `Status` Literal; `page>=1`, `page_size<=100`; `record_out` fills defaults and converts nested dates. |
| 16 | `health` (l.72-74) | Always returns `ok`, even when MongoDB is down. | Stop mongod, `GET /health` still 200. | Pings Mongo; 503 on failure. Also retries index creation if startup could not reach Mongo. |
| 17 | whole file | No indexes at all and no startup index creation; `serverSelectionTimeoutMS` not set (a dead DB hangs requests for 30 s). | `explain` on any list query shows COLLSCAN. | `ensure_indexes()` in the FastAPI lifespan (idempotent, named indexes); 5 s server-selection timeout; `PyMongoError` handler returns 503 not 500. |

## Looked at and decided it is fine
* `load_dotenv()` with its default `override=False`: real environment variables already win over `.env`, as required.
* `doc.pop("_id", None)` after `insert_one` in `create_employee`: correct; `insert_one` mutates the dict, so removing `_id` is needed.
* `find(q, {"_id": 0})` projection in `list_employees` is fine.
* `def` (sync) endpoints with the sync PyMongo driver: FastAPI runs them in a threadpool, so they do not block the event loop. `MongoClient` is thread-safe and is shared on purpose.
* `department` filter on `GET /employees` is an exact, case-sensitive match, as the contract says.
